## 丰田 TSS2 原车跟车距离改造（卡罗拉 2020+）

需求：原车三档跟车距离可用，且能用方向盘车距键控制。

根因：`carcontroller.py` 原逻辑 `desired_distance = 4 - leadDistanceBars`，只要原车档位与 openpilot 的 personality 不一致就发 `ACC_CONTROL.DISTANCE` 脉冲把档位顶回去 → 驾驶员按键换挡被立刻改回。

关键信号（opendbc 已核实）：
- `PCM_CRUISE_2`(0x1D3) `PCM_FOLLOW_DISTANCE` 2bit：1=far / 2=medium / 3=close，原车档位权威来源
- `ACC_CONTROL`(0x343) `DISTANCE` 1bit：请求换挡脉冲，openpilot 自己也发，TSS2 无雷达车型从 cp_cam 读回是**自身回环**，不能当按键用
- 卡罗拉 TSS2 = `CAR.COROLLA_TSS2` ∈ `TSS2_CAR - RADAR_ACC_CAR`（无雷达 ACC），不在 `UNSUPPORTED_DSU_CAR`

改动（commit 516f267）：
- `cereal/car.capnp`：CarState 新增 `pcmFollowDistance @80 :UInt8`（原最大编号 79）
- `carstate.py`：读 PCM_FOLLOW_DISTANCE，过滤无效值 0（上电瞬间），写入 pcmFollowDistance
- `carcontroller.py`：不再发 DISTANCE 脉冲改写原车档位
- `interface.py`：停用基于 ACC_CONTROL.DISTANCE 的 gapAdjustCruise 事件
- `controlsd.py`：新增 `PCM_DISTANCE_TO_PERSONALITY` + `update_personality_from_pcm_distance()`；params_thread 收到有效档位后停止从 params 反向覆盖；删除原 gapAdjustCruise 递减逻辑
- 两个 `long_mpc.py`（legacy / 非 legacy，由 `dp_0813` 参数决定用哪个）：get_T_FOLLOW 改 2.2 / 1.8 / 1.4 秒，get_dynamic_follow 曲线终点同步对齐

映射链：档位1(far)→relaxed(2)→2.2s→3条；档位2(medium)→standard(1)→1.8s→2条；档位3(close)→aggressive(0)→1.4s→1条。已用脚本校验 bars == 4 - 档位。

待实车验证：按方向盘车距键后 PCM_FOLLOW_DISTANCE 是否真的变化。若信号不变，说明该年款 PCM 在 openpilot 纵向接管时忽略按键，需另找按键报文。

## 关键工程结论（重要）

- **cereal 无需重新编译**：`cereal/__init__.py` 用 `capnp.load('car.capnp')` 在运行时动态加载 schema，改 `.capnp` 后 Python 侧立即生效。仓库里 `cereal/libcereal_shared.so` 是预编译的 C++ 端，capnp 向后兼容，旧 reader 会保留/跳过未知字段，不会破坏通信。
- 仓库**没有顶层 SConstruct**，也没有 `selfdrive/test/`。Legacypilot 剥离了测试套件，改 MPC 数值不会触发测试断言失败。
- `create_button_events` 停用后必须从 interface.py 的 import 中移除，否则 flake8 F401。

## 车型画像核实：卡罗拉 21 PLUS TSS2（用户确认有前雷达）

**重要概念区分（易错）**：
- 用户车 = CAR.COROLLA_TSS2，**确实有前毫米波雷达**：`DBC[COROLLA_TSS2]['radar'] = 'toyota_tss2_adas'`，故 `radarUnavailable = False`
- openpilot 的 `RADAR_ACC_CAR` 只含 {RAV4_TSS2_2022, RAV4_TSS2_2023, CHR_TSS2}，含义是**ACC 由雷达 ECU 主导**，不是"车有没有雷达"
- 之前说的"TSS2 无雷达ACC车型"是集合 `TSS2_CAR - RADAR_ACC_CAR` 的直译 = ACC 由前视相机主导，**表述容易误读，以后要说清**

卡罗拉 TSS2 完整画像：
| 项 | 值 | 依据 |
|---|---|---|
| 前雷达 | 有 | DBC radar=toyota_tss2_adas，radarUnavailable=False |
| DSU | 无 | COROLLA_TSS2 ∈ NO_DSU_CAR（= TSS2_CAR ∪ {CHR, CAMRY}）|
| ACC 主导 | 前视相机 | ∉ RADAR_ACC_CAR |
| openpilot 纵向 | 可用 | openpilotLongitudinalControl = ... or candidate in (TSS2_CAR - RADAR_ACC_CAR) |
| pt DBC | toyota_nodsu_pt_generated | values.py |

**有雷达不影响改造**：
- 雷达 DBC（toyota_tss2_adas）里 grep 不到 DISTANCE/FOLLOW 信号 → 雷达不产生跟车档位
- 跟车档位唯一权威来源仍是 PCM_CRUISE_2.PCM_FOLLOW_DISTANCE
- 卡罗拉不在 RADAR_ACC_CAR → openpilot 纵向时不禁用雷达，雷达继续供 lead，跟车时距仍由 MPC 的 TR 决定

**DBC 中不存在方向盘车距按键的独立 CAN 报文**（方向盘 SPI → PCM），所以读 PCM 输出是唯一可行路径。

**交叉验证信号**：`PCM_CRUISE_SM (0x399, PCM_CRUISE_SM).DISTANCE_LINES` 2bit，
VAL_ 921: 0=不显示 1=close 2=medium 3=far —— **方向与 PCM_FOLLOW_DISTANCE 相反**。
它变化即证明 PCM 收到了按键，可用于区分"PCM 不响应"与"openpilot 解析有问题"。
openpilot 的 CAN 消息列表里已包含 PCM_CRUISE_SM（1Hz），但未解析该信号。
